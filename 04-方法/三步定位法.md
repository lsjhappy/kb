# 三步定位法（通用）

> 任何故障都先走这三步，**能解决 80% 的问题**。

## 第一步：分清"是谁的问题"

系统里永远只有三种角色：

1. **生产端**（有人往里写吗？）
2. **中间件**（数据在管道里吗？）
3. **消费端**（有人取出来处理吗？）

**先确认哪一段断了，别一上来就重启。**

## 第二步：找"卡在哪个点"

按数据流顺序，从**上游往下游**推：

```
上游有没有数据产生？  没有 → 问题在上游
       │有
       ▼
中间件有没有积压？    积压 → 问题在消费端慢/挂
       │没积压
       ▼
下游有没有写入？      没写 → 问题在消费逻辑
```

**每一步只需要一个判断，不要同时查三个。**

## 第三步：确认改动前先备份

要动配置/重启之前：

1. **先导出当前状态**（`ps`、配置、库里的记录）
2. 想清楚**如果错了怎么退回去**
3. 再动手

> **没有回滚方案，就不要改生产。**

## 什么时候用这个

| 场景 | 用哪步 |
|---|---|
| 数据不同步 | 第一 + 第二步 |
| 服务起不来 | 第一步（看日志） |
| 慢了/积压 | 第二步 |
| 要改配置 | 第三步 |

## 一句话

**先定位，再动手。** 90% 的"越修越坏"，都是因为没定位就动手。
